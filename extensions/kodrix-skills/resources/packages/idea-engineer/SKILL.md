# Idea Engineer

让软件开发回归想法本身。从一句话想法到完整可运行的产品。

## When to use

- 你有一个模糊的产品想法，需要 AI 帮你分析和落地
- 想快速验证一个创业点子或功能构思
- 需要从零开始构建完整项目但不确定从何入手
- 有抽象概念需要转化为具体的技术方案

## Workflow

### 1. 想法捕获
描述你的想法，越具体越好。包括：
- 目标用户是谁
- 要解决什么问题
- 期望的核心功能
- 偏好的技术栈（如果有）

### 2. 深度分析（LLM 驱动）
Idea Engineer 会使用 LLM 对想法进行深度分析：
- 市场需求定位
- 技术可行性评估
- 技术栈推荐
- 架构风格建议
- 复杂度评估
- 功能优先级排序

### 3. 自动规划
基于分析结果自动生成：
- **Requirements** — 产品需求文档（用户故事 + 验收标准）
- **Design** — 架构设计文档（系统架构 + 数据模型 + API 设计）
- **Tasks** — 任务分解文档（按优先级排序的实施任务）
- **Agent Crew** — 多智能体协作配置（角色分配 + 任务依赖图）

### 4. 实施构建
自动进入构建阶段：
- 按 Architect → Coder → Tester 顺序编排 Agent
- 实时跟踪构建进度
- 自动检测构建完成状态

### 5. 验证与预览
- 自动启动开发服务器
- 在 Preview 中加载运行中的应用
- 收集反馈进行迭代

### 6. 知识沉淀
- 自动将项目知识沉淀到 Learning Engine
- 技术选型和架构决策被记录下来
- 下次类似项目可复用

## Best Practices

- **从简单开始**：先描述最小可行产品（MVP），再迭代增加功能
- **具体化想法**：想法越具体，分析越准确。包括目标用户、核心场景、技术偏好
- **利用模板**：从预设模板（博客、看板、聊天、仪表盘、电商）快速开始
- **语音输入**：支持语音输入想法，更自然的表达方式
- **多轮迭代**：首次构建后可以继续使用 AI 进行增量修改

## Agent Prompt

你是一个资深产品经理和技术架构师。用户有一个软件想法需要你帮助分析和落地。你的任务是：

1. 与用户深入交流，充分理解想法
2. 进行技术可行性和市场定位分析
3. 推荐最优技术栈和架构方案
4. 将想法分解为可执行的功能模块
5. 生成完整的 Spec 文档和任务列表

始终保持「让软件开发回归想法本身」的核心理念 — 用户只需要提供想法，技术细节由 AI 负责。
