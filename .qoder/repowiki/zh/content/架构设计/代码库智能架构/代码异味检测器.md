## 简介
本仓库是 Kodrix Code，基于 VS Code/VSCodium 深度定制的 AI 原生编辑器。围绕"Agent OS、Skill 市场、本地模型 BYOK"三大扩展，本次文档聚焦"代码异味检测器"这一能力：通过静态规则与 LLM 辅助生成，识别过大文件、高耦合、循环依赖、未使用导出、**过长函数**等异味，并输出结构化报告，辅助重构与质量治理。该能力在审计报告中作为 P1 差异化能力之一被实现与闭环。

**更新** 现已支持6种代码异味检测类型，包括新增的过长函数检测功能。

## 项目结构
- 根目录提供构建、脚本、补丁、测试与产品配置；核心源码位于 src/，内置扩展位于 extensions/。
- 三个 kodrix 扩展各自承担职责：
  - kodrix-agent-os：Agent OS、Idea Flow、Spec、Wiki、Crew、Checkpoint、Codebase 等
  - kodrix-local：本地模型、BYOK、迁移、Cursor 对标编排
  - kodrix-skills：Skill 市场（侧栏/Webview/安装卸载）

## 详细组件分析

### 组件：增强的代码异味检测器（6种静态规则 + LLM 辅助）
- **目标**：识别并报告常见代码异味，降低技术债累积
- **关键规则**（已扩展至6种）：
  - 过大文件：单文件行数/复杂度阈值（>500行估算）
  - 高耦合：跨模块引用密度过高（依赖数 > 15）
  - 循环依赖：模块间环状引用（DFS算法检测）
  - 未使用导出：声明但未在工程内引用（exportCount > 2且无反向依赖）
  - **过长函数**：**新增**：函数或方法行数超过阈值（>200行）
  - LLM辅助：可选的智能分析与建议生成
- **降级策略**：无 LLM 时仅运行静态规则，仍产出基础报告
- **产物**：CODE_SMELLS.md（Markdown 表格/清单，便于审阅与自动化）

**更新** 新增的第6种检测类型"过长函数检测"通过遍历项目索引中的符号，识别函数和方法的行数超过200行的代码异味。

### 组件：过长函数检测实现细节
**新增功能** 第6种检测类型的具体实现：

- **检测逻辑**：遍历项目索引中的所有符号，筛选出类型为 Function 或 Method 的符号
- **长度计算**：通过 `sym.endLine - sym.line` 计算函数行数
- **阈值设置**：默认阈值为200行，可通过 `LONG_FUNCTION_THRESHOLD` 常量配置
- **结果输出**：生成包含函数名称、文件路径、行号、严重度的检测记录
- **国际化支持**：使用 `l10n.t()` 提供多语言消息支持

**技术实现**
- 使用 `SymbolKind.Function` 和 `SymbolKind.Method` 进行类型判断
- 利用 `ProjectIndex.symbols` 获取完整的符号信息
- 通过 `path.relative()` 生成相对路径
- 支持行号定位，便于快速跳转到问题位置

## 性能与可维护性考量
- 增量与防抖：索引更新采用防抖减少频繁写入，避免 IO 抖动
- 缓存：查询结果可缓存（TTL + maxEntries），提升重复操作性能
- 降级：无 LLM 时仍可运行静态规则，保障基本可用性
- 可扩展：规则以模块化方式组织，便于新增与灰度发布
- 可观测：通过日志与报告输出，便于定位问题与度量效果
- **性能优化**：过长函数检测通过 ProjectIndex 直接获取符号信息，避免重复解析源码

**更新** 新增的过长函数检测充分利用了现有的 ProjectIndex 数据结构，无需额外的源码解析开销。

## 故障排查指南
- 若无法生成报告：检查是否已构建索引、是否存在权限问题导致无法写入 CODE_SMELLS.md
- 若 LLM 辅助失败：确认 BYOK 配置正确、网络可达、API Key 有效；必要时回退到纯静态规则
- 若命令不可用：核对 package.json 中命令注册与快捷键绑定是否正确
- 若界面文案异常：确认 NLS 文件 key 与 %key% 引用一致
- **过长函数检测问题**：检查 ProjectIndex 是否正确包含符号信息，确认 SymbolKind 枚举值正确
