## 简介
本文件面向管理员与用户，系统化说明 Kodrix 的配置体系：产品级配置（product.json）、用户设置、工作区配置等多层次结构；关键配置项的作用与默认值（模型供应商、功能开关、UI 定制等）；配置的优先级与继承机制；配置验证与错误处理；配置模板与最佳实践；以及迁移与版本兼容性管理。目标是帮助团队统一配置标准，降低排错成本，提升可维护性。

**重要更新**：Kodrix 现已集成 SecretStorage 安全存储机制，所有 API 密钥和敏感信息都通过加密存储，不再以明文形式保存在 settings.json 中，大幅提升配置安全性。同时优化了项目依赖管理配置，提升了构建系统的清晰度和可维护性。

### SecretStorage 安全存储机制
**新增功能**：Kodrix 现已全面集成 VS Code 的 SecretStorage 机制，为敏感配置提供企业级的安全存储。

- **支持的密钥类型**
  - FIM API Key：`kodrix.agent-os.tabCompletion.fimApiKey`
  - Embedding API Key：`kodrix.agent-os.semanticEmbedding.apiKey`
  - 供应商 API Key：`kodrix.apiKey.{providerId}`

- **存储特性**
  - 使用操作系统级别的加密存储（Windows DPAPI、macOS Keychain、Linux libsecret）
  - 密钥不会以明文形式出现在任何配置文件或日志中
  - 支持密钥的增删改查操作
  - 自动清理空值和无效密钥

- **设置页面集成**
  - 提供图形化界面管理敏感配置
  - 实时显示密钥配置状态
  - 支持一键清除和重新配置

## 性能考虑
- 配置加载开销
  - 尽量减少大型 JSON 结构与深层嵌套，避免启动时解析耗时
  - **新增** SecretStorage 访问采用异步操作，避免阻塞主线程
- 缓存与增量
  - 对频繁读取的配置项（如默认代理、市场地址）进行内存缓存
  - **新增** SecretStorage 结果缓存，减少重复的加密存储访问
- 网络端点
  - 合理设置超时与重试，避免阻塞启动流程
- **优化** 依赖加载
  - 分类依赖有助于按需加载，减少不必要的依赖解析时间
  - optionalDependencies 的安装失败不会影响核心功能启动

## 故障排查指南
- 常见症状
  - 启动崩溃：检查 product.json 是否包含必需字段（如共享数据目录）
  - 无法连接市场：核对扩展市场地址与受信任域名
  - 密钥无效：**更新**确认未将密钥写入 settings.json，改用 SecretStorage
  - 设置页面问题：检查 webview 是否正常加载
  - 依赖安装失败：**优化**检查 optionalDependencies 是否安装成功，不影响核心功能
- 诊断步骤
  - 查看构建日志，确认 product.json 是否被正确读取与注入
  - 检查用户与工作区设置是否存在语法错误或冲突
  - 使用配置编辑扩展进行可视化校验与提示
  - **新增** 通过设置页面检查 SecretStorage 中的密钥状态
  - **优化** 检查 package.json 依赖分类是否正确，特别是 _outdatedDependencies 中的升级建议
- 修复建议
  - 使用幂等修复脚本补齐缺失字段
  - 清理冲突的工作区设置，逐步回退定位问题
  - 审计外部端点与白名单，移除不再使用的域名
  - **新增** 使用设置页面重新配置敏感信息
  - **优化** 按照 _outdatedDependencies 中的说明逐步升级依赖
