- 补丁文件名采用两位数字前缀（如 `00-`、`10-`、`20-`、`40-`、`70-`）表示应用优先级，数字越大越晚生效。
- 跨平台差异通过子目录隔离：`linux/`、`windows/`、`osx/`、`alpine/`、`insider/` 各自存放对应平台的补丁，避免交叉污染。
- 架构扩展类补丁统一使用 `NN-arch-add-*.patch` 命名（如 `41-arch-add-support.patch`、`42-arch-add-ppc64le.patch`），并在 `BUILD_TARGETS`、sysroot 校验、依赖列表等处同步注册新架构。
- 品牌定制通过全局字符串替换实现，将 `VS Code` / `Visual Studio Code` 等字样替换为占位符 `!!APP_NAME!!`，由后续构建阶段注入实际产品名。
- 构建期行为开关通过修改 `build/gulpfile.*.ts`、`build/azure-pipelines/*` 中的常量或条件分支完成，例如关闭 esbuild、mangle、签名验证、遥测、更新检查等。
- 每个补丁仅聚焦单一变更主题（如 `00-build-disable-esbuild.patch`、`00-telemetry-disable.patch`、`00-security-add-command-filter.patch`），便于独立维护与回滚。
