本模块是 VS Code 源码树中的扩展根目录，每个子目录对应一个独立的 VS Code 扩展包，按职责分为四类：
- 纯语法/片段扩展（如 bat、clojure、css、go、java、json、yaml 等）：仅包含 `syntaxes/*.tmLanguage.json`、`snippets/*.code-snippets`、`language-configuration.json` 和最小化的 `package.json`，无编译产物。
- 语言特性扩展（如 `html-language-features`、`css-language-features`、`json-language-features`、`typescript-language-features`、`markdown-language-features`）：采用 client/server 双端架构，`client/` 在 VS Code 进程运行，`server/` 作为 LSP 服务器独立启动；均提供 `esbuild.browser.mts` 与 `esbuild.mts` 分别构建浏览器端与 Node 端。
- 功能型扩展（如 `git`、`github`、`debug-auto-launch`、`media-preview`、`ipynb`、`mermaid-markdown-features`、`simple-browser`、`tunnel-forwarding`）：以 TypeScript 编写，经 esbuild 打包为 `out/` 或 `dist/`，并通过 `package.nls.json` 提供多语言资源。
- 主题扩展（如 `theme-defaults`、`theme-monokai`、`theme-seti`）：仅含 `themes/*.json` 与图标资源。

构建体系由顶层共享脚本统一驱动：`esbuild-common.mts` 提供基于 `@parcel/watcher` 的增量 watch 与单例 esbuild 服务管理；`esbuild-extension-common.mts` 封装 Node/Browser 平台差异（external vscode、process.platform 替换、alias path-browserify）；`esbuild-webview-common.mts` 固定 webview 构建选项（ESM、不生成 sourcemap）。所有扩展通过各自的 `esbuild.mts` / `esbuild.browser.mts` 复用这些公共配置。TypeScript 编译统一继承 `tsconfig.base.json`（ES2024 target、strict、noUnusedLocals/Parameters 等严格规则）。安装阶段 `postinstall.mjs` 会裁剪 `node_modules/typescript` 体积，仅保留 `lib` 与 `package.json`，并删除 `.d.ts` 与 tsc 运行时文件。各扩展通过自身 `package.json` 声明 `contributes.*`（grammars、languages、commands、views、webviews 等）向 VS Code 注册能力，彼此之间无直接依赖，仅通过 VS Code API 交互。
