根目录是 VSCode 上游代码的镜像与定制层：product.json 把品牌名、数据目录、扩展市场（open-vsx.org）、默认聊天代理（GitHub Copilot）和 tunnel 配置注入到所有运行时；build/gulpfile.ts（由 gulpfile.mjs 转发）统一编排 src、extensions/*/、cli、test 等多子工程的编译、打包与产物合并；Directory.Build.props 向 MSBuild 子树注入跨平台属性；.npmrc + package.json 锁定 Node/Electron 依赖并声明 preinstall/postinstall 钩子驱动 build/npm 下的安装流程。子模块之间不直接互相引用，而是通过三层契约耦合：
- 运行时契约：core_runtime 暴露 out/main.js 作为 Electron 入口，remote_runtime 提供 server/web 两套 npm 依赖清单，cli_tool 提供 code 可执行文件。
- 资源契约：resources_platform 提供各 OS 启动脚本与图标，被 build 脚本在打包阶段嵌入。
- 配置契约：product.json 与 extensions/kodrix-skills/resources/catalog.json 共同决定内置扩展启用策略与 Skill 注册表。
CI 由 github_config 中的 GitHub Actions 工作流触发，使用 patches 对上游 diff 进行应用后再走根级 npm 脚本完成发布。
