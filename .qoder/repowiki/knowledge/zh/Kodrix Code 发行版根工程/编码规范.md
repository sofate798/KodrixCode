- 所有跨子模块的配置（品牌名、数据目录、扩展市场 URL、tunnel 配置、默认聊天代理）集中维护在 product.json，子模块只读取该 JSON 而不硬编码常量。
- 构建与任务编排统一通过 gulpfile.mjs 转发到 build/gulpfile.ts，新增构建步骤应在此处注册而非在各子模块各自定义。
- 对上游 VSCode 源码的修改以 patches/*.patch 形式提交，禁止直接修改 src 中属于上游的文件，确保补丁可重新应用。
- 扩展的 API 提案启用与运行位置通过 product.json 中的 extensionEnabledApiProposals / builtInExtensionsEnabledWithAutoUpdates 字段声明，而非在扩展自身 manifest 中开启。
