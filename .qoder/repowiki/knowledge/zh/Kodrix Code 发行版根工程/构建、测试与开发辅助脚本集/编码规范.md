- 每个可执行入口都提供三件套：Unix shell (`*.sh`)、Windows batch (`*.bat`)、Node 实现 (`*.js`)，三者职责一致但分别处理路径与平台差异。
- 脚本通过 `node -p "require('./product.json').nameLong|nameShort|applicationName"` 动态读取产物名称，而非硬编码二进制名。
- 开发模式通过导出 `VSCODE_DEV=1`、`NODE_ENV=development`、`ELECTRON_ENABLE_LOGGING=1` 等环境变量切换行为，并在 WSL/Docker 等特殊宿主下做条件分支。
- 测试脚本统一将崩溃转储目录设为 `$ROOT/.build/crashes`，并以 `--crash-reporter-directory` 传给 Electron 测试入口。
- chat-simulation 的场景文件以 `_chatperf_<domain>.ts` 命名并按领域拆分（strings、types、uri、event、lifecycle、arrays、async、errors），由公共 runner 聚合执行。
