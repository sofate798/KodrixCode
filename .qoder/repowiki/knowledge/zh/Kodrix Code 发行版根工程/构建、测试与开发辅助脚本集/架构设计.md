模块按用途分为三层：
- `dev/`：VSCodium 分支的顶层构建编排层，`build.sh`（及 `build.ps1`）通过解析参数设置 `OS_NAME`/`VSCODE_ARCH`/`SKIP_*` 等环境变量后调用上游 `vscode/build.sh`，并负责 patch 管理 (`patch.sh`、`merge-patches.sh`)、API 同步 (`update_api.sh`) 与 macOS 代码签名环境加载。
- `scripts/`：VS Code 源码自带的运行时与测试入口，按二进制形态成对存在 `.sh`/`.bat`/`.js`（如 `code.sh`→`code.js`、`code-server.*`、`code-web.*`、`code-sessions-web.*`），统一通过 `product.json` 解析产物名并注入 `VSCODE_DEV=1`、`NODE_ENV=development` 等环境变量后 exec 到 Electron 或 Node 进程；`test*.sh`/`test*.bat` 系列则封装单元、Web、远程集成测试的启动命令。
- `scripts/chat-simulation/`：独立的聊天场景仿真子系统，基于 `config.jsonc` 配置性能回归阈值与内存泄漏阈值，由 `test-chat-perf-regression.js` 与 `test-chat-mem-leaks.js` 驱动，`fixtures/_chatperf_*.ts` 定义各场景输入，`common/mock-llm-server.ts` 提供模拟 LLM 后端。
依赖方向单向：`dev/*` 调用上游 `vscode/build.sh`，`scripts/*` 仅消费已构建产物（`.build/electron/*`），`chat-simulation` 不反向依赖构建流程。
