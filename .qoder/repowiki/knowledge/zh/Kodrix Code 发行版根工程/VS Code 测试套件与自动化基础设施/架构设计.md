本模块按测试类型划分为多个独立子项目，每个子目录是一个可单独构建/运行的 npm 包：
- `automation/src`：核心自动化库，提供 `Application`、`Code`、`Editor`、`Terminal`、`Explorer` 等高层 UI 操作封装，并通过 `index.ts` 统一导出；同时暴露 `getDevElectronPath/getBuildElectronPath/getBuildVersion` 用于定位 VS Code 二进制。
- `smoke`：基于 Mocha + `@vscode/test-electron` 的端到端冒烟测试入口 `src/main.ts`，通过 `minimist` 解析 `--web/--remote/--build/--headless/--tracing` 等参数，在 Electron/Web/Remote 三种模式下启动 VS Code，并动态 `import('./areas/...')` 注册各功能域（terminal、chat、extensions、workbench 等）的测试套件。
- `integration`：API 级集成测试，`electron/testrunner.js` 作为 Electron 宿主加载被测代码，`browser` 子项目提供浏览器端集成测试入口。
- `unit`：Node/Electron/Browser 三套 Mocha 运行器，`node/index.js` 通过 glob 扫描 `out*/**/*.test.js`，注入 `_VSCODE_PRODUCT_JSON/_VSCODE_FILE_ROOT` 等全局后以 TDD 模式执行，并支持 `--run/--runGlob/--coverage` 过滤与覆盖率输出。
- `sanity`：发布前健康检查测试，`src/main.ts` 组装 `TestContext` 并调用 cli/desktop/serverWeb/wsl/devTunnel 等测试组，配合 `scripts/run-docker.sh/.cmd` 在多平台容器内执行。
- `mcp`：MCP 协议测试服务，复用 `automation` 中的 `Application`，通过 stdio 通道暴露 `automationTools/*`（activityBar/chat/editor/explorer 等）供 MCP 客户端调用。
- `componentFixtures/playwright`：基于 Playwright 的组件快照测试，使用 `utils.ts` 打开 fixture 页面并断言 DOM 状态。
- `monaco`：Monaco 编辑器专项测试，使用 webpack 打包 + Mocha runner，并提供 ESM 兼容性检查脚本。
依赖方向单向：`smoke`、`sanity`、`mcp` 均依赖 `automation`；`unit` 直接加载编译产物 `out*`；各子项目之间无相互引用，仅共享仓库根路径约定（`.build/logs`、`.build/crashes`）。
