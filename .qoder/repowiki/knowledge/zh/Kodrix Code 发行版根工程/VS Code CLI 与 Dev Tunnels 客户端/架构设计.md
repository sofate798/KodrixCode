模块以 `Cargo.toml` 同时产出库 (`cli`) 与二进制 (`code`)：
- 入口 `src/bin/code/main.rs` 通过 clap derive 解析参数，区分 Integrated/Standalone 两种模式，并委派到 `commands::*` 下的具体子命令处理器。
- `src/lib.rs` 暴露公共 API 面：`auth`、`constants`、`log`、`commands`、`desktop`、`options`、`self_update`、`state`、`tunnels`、`update_service`、`util`；内部模块 `async_pipe`、`download_cache`、`json_rpc`、`msgpack_rpc`、`rpc`、`singleton` 不对外导出。
- `commands/` 按功能域拆分：agent 系列（host/ps/logs/stop/kill）、`serve_web`、`tunnels`、`update`、`version`，共享 `CommandContext`（HTTP 客户端 + 路径 + 日志 + 参数）。
- `tunnels/` 是独立的隧道子系统，复用上游 `tunnels` crate（dev-tunnels），实现控制服务器、端口转发、本地转发、单例进程通信、平台服务封装（service_linux/macos/windows）、nosleep 抑制器（按 target_os 条件编译）等。
- `desktop/` 仅含 `version_manager.rs`，用于发现/启动已安装的 VS Code 编辑器二进制。
- `build.rs` 在构建期从仓库根 `product.json`/`package.json` 注入 `VSCODE_CLI_*` 环境变量，并在 Windows 上通过 `winresource` 写入版本资源，同时校验所有 `.rs` 文件头包含微软版权注释。
- 依赖方向单向：bin → commands → tunnels/util/desktop；tunnels 层向上只暴露 `serve`/`ServiceManager`/`SleepInhibitor` 等有限接口。
