⑦ 追赶路线图（建议优先级）

基于差距分析，按「投入产出比」排列的追赶建议。不追求 1:1 复制 Cursor，而是以 Kodrix 开源+本地优势为基础选择性追赶。

Phase A · 本地可闭环（1-2 周）

无需服务端，纯客户端可实现
  • A1 Multi-Agent 真并行：基于 git worktree 的本地多 Agent 隔离执行 + Agents Window 平铺面板
  • A2 Auto-Review 分级审批：Allow-list 配置 + 操作分类器 + 自动/确认/拒绝三级
  • A3 Composer 自动验证循环：Apply 后自动 lint/typecheck/test，失败自动修复重试
  • A4 Automations 模板引擎：在 Hooks 基础上扩展无代码模板（本地执行）

Phase B · 需轻量服务（2-4 周）

需 GitHub App / Webhook / 轻量后端
  • B1 Bugbot 式 PR 审查：GitHub App + Webhook 触发 → Agent 审查 → 评论 API 反馈
  • B2 Background Agent (Codespaces)：对接 GitHub Codespaces / Dev Container 作为远程执行环境
  • B3 Shared Canvas 导出：Webview → 静态 HTML 导出 + 本地 HTTP 分享链接

Phase C · 需完整后端（长期）

需账号体系 + 云基础设施 + 持续运维
  • C1 云端 Background Agent：自建容器编排 + 代码隔离沙箱
  • C2 Teams 协作：账号体系 + 权限管理 + Rules 共享 + 统一配置
  • C3 实时 Shared Canvases：WebSocket 同步 + 协作编辑
  • C4 Self-hosted 企业版：私有部署 + 审计日志 + SSO
策略建议：优先完成 Phase A（本地可闭环，投入小收益大），Phase B 按需启动（Bugbot 是高频需求），Phase C 作为商业化长期目标。 Kodrix 的核心竞争力在于「开源 + 本地智能 + 越用越聪明」，不必完全复制 Cursor 的云路线。
