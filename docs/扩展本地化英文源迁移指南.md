# 扩展本地化迁移指南（英文源 + 双语言包）

> 2026-10-04 制定，**2026-10-05 三扩展迁移全部完成**。本文档记录 Kodrix 扩展层（`extensions/kodrix-*`）的本地化形态、维护规则与工具链，供后续新增文案时遵循。

## 最终形态（已完成）

产品自带两个语言包：**简体中文（默认）+ 英语**，无其他语言。

| 层 | 机制 | 状态 |
|---|---|---|
| VS Code 核心 `src/vs/**` | `localize()` 英文源 + `extensions/ms-ceintl.vscode-language-pack-zh-hans/translations/main.i18n.json`（dev 由 `scripts/apply-zh-langpack.mjs` 注入 `out/vs/nls.js`，发布由 `apply-release-zh-langpack.mjs` 重写 `nls.messages.json`） | ✅ 已合规 |
| 扩展 `package.json` 命令标题 | `%command.xxx%` + `package.nls.json`（英文）+ `package.nls.zh-cn.json`（中文） | ✅ 三扩展合规 |
| 扩展源码 UI 字符串 | **英文源** `l10n.t('English…')` + `l10n/bundle.l10n.json`（英文恒等，工具校验用）+ `l10n/bundle.l10n.zh-cn.json`（英文键→中文译文） | ✅ 三扩展迁移完成 |

语言包规模：**kodrix-skills 90 键 · kodrix-local 267 键（含 19 个数据键）· kodrix-agent-os 1052 键**，全部 zh-cn 完整。

### 加载机制（`src/vs/workbench/api/common/extHostLocalizationService.ts`）

- 界面语言 = 英语（默认）：`l10n.t()` 直接返回源串，**不加载任何 bundle** → 英文源即英文界面。
- 界面语言 = zh-cn：加载 `l10n/bundle.l10n.zh-cn.json`，按键覆盖；缺键时告警并回退英文源。
- 扩展 `package.json` 必须声明 `"l10n": "./l10n"`。

## 迁移流程（以扩展为单位）

1. **盘点**：`node scripts/kodrix-l10n.mjs scan --ext <ext>` 列出未包裹的裸字面量（通知 / placeHolder / prompt / title）。
2. **改写源码为英文源**：
   - 已有 `l10n.t('中文')` → 把键改为英文；硬编码的用户可见中文字符串 → 包裹 `l10n.t('English…')`。
   - 模板串 `` `已安装 ${name}` `` → `l10n.t('Installed {0}', name)`（`{0}`~`{9}` 占位）。
   - 抛给用户看的 `throw new Error()` 消息同样包裹（会经 `showErrorMessage` 显示）；`_diag` / console 日志**不本地化**（排障需统一语言检索，本项目约定保留）。
   - **不要**用"错误消息文本前缀匹配"做控制流（译文随语言变化）——改为专用错误类 `instanceof`（参考 `skillInstall.ts` 的 `SkillExistsError`）。
3. **WebView HTML**（`resources/*.html`）：
   - 静态文案 → `{{l10n:English text}}` 占位符，宿主侧替换（参考 `marketplaceWebview.ts` 的 `L10N_PLACEHOLDER_RE` / `localizeWebviewText`；agent-os 已有 `src/shared/webviewHtml.ts` 同款实现）。
   - 脚本侧动态文案（badge / 按钮 label / 空态）→ 宿主侧建字典 `buildWebviewL10nDict()`（每项都是字面量 `l10n.t('…')`），经 `{{l10nDict}}` 占位注入为 `const L10N = {...}`；`<html lang>` 用 `{{htmlLang}}` 注入 `vscode.env.language`。
   - 占位符内不能出现 `}` 与未转义的 `"`；JSON 注入需 `.replace(/</g, '\\u003c')` 防 `</script>` 逃逸。
4. **重新生成 bundle**：`node scripts/kodrix-l10n.mjs extract --ext <ext>`（生成英文恒等 `bundle.l10n.json`，同时收录 HTML `{{l10n:}}` 占位键）。
5. **编写中文包** `l10n/bundle.l10n.zh-cn.json`：键 = bundle.l10n.json 的全部键，值 = 中文译文。占位符 `{0}` 位置可按中文语序调整。
6. **更新测试**：单测中对中文错误消息的断言改为英文；注意 `vscode-mock` 需在被测模块**之前** require（被测模块依赖 `vscode.l10n` 时，ES import 会被提升，须改用 `require` 顺序加载，见 `zipValidation.test.ts`）。mock 的 `l10n.t` 是恒等实现。
7. **校验**（全部通过才算完成）：
   ```bash
   node scripts/kodrix-l10n.mjs check            # bundle 一致性 + zh-cn 包键集完整性
   cd extensions/<ext> && npm run compile:test   # tsc 类型检查
   node ./out-test/test/runTests.js              # 单元测试
   ```

## 日常维护规则（新增/修改文案时）

1. **新增 UI 字符串**：源码写 `l10n.t('English source')`；模板串用 `{0}`~`{9}` 占位。
2. **改完必须三步**：
   ```bash
   node scripts/kodrix-l10n.mjs extract          # 同步 bundle.l10n.json（新键入包）
   # 手工为 l10n/bundle.l10n.zh-cn.json 补新键的中文译文（extract 不会自动翻译）
   node scripts/kodrix-l10n.mjs check            # 校验一致性 + zh-cn 完整性（缺译即失败）
   ```
3. **WebView**：静态文案用 `{{l10n:English}}` 占位（agent-os 走 `loadWebviewHtml`，local/skills 各自 getHtml 内置管线）；脚本侧动态文案用宿主字典 + `{{l10nDict}}` 注入（参考 `marketplaceWebview.ts` / `providerWorkbench.ts`）或模板串插值（`settingsPage.ts` 的 `WEBVIEW_TEXT` + `jsJson()`）。
4. **数据驱动文案**（presets.json / catalog.json 等）：数据文件写英文，运行时 `l10n.t(p.name)` 回填，键登记在 `l10n/data-keys.json`（目前仅 kodrix-local 有）。
5. **不要用消息文本匹配做控制流**——译文随语言变化；用专用错误类 `instanceof`（参考 `skillInstall.ts` 的 `SkillExistsError`）。

## 明确不本地化的内容（约定）

- **发给 AI 模型的提示词与工具描述**（systemPrompt、tool description、注入模型的上下文）：保持中文。它们面向模型而非用户；随界面语言切换会改变模型行为，且中文提示词对国产模型效果更好。
- **console / logger / _diag 日志**：保持中文，便于排障时统一语言检索。
- **匹配中文用户输入的正则/关键词**（意图识别、功能提取等）：属功能逻辑，不动。

## 校验工具（`scripts/kodrix-l10n.mjs`）

- `extract`：源码静态 `l10n.t` + HTML `{{l10n:}}` + `l10n/data-keys.json` → `bundle.l10n.json`
- `check`：① 源码键都在 bundle ② bundle 无失效键 ③ zh-cn 包键集完全一致（缺译/失效均失败）④ `package.json` 含 `"l10n": "./l10n"`
- `scan`：盘点未包裹的裸字面量
- `wrap --apply`：自动包裹裸字面量（中文源遗留收口用）
- 注释剥离是**字符串感知**的（2026-10-05 修复：字符串里的 `/*` 曾导致整段代码被误当注释、l10n 键静默漏采）

## 迁移期间的一次性工具

`scripts/kodrix-l10n-migrate.mjs`（保留备用）：按 zh→en 映射表批量改写源码 `l10n.t()` 键与 HTML `{{l10n:}}` 占位。仅在未来出现新的中文源模块需要批量迁移时使用。

## 已知注意点

- 改 `src/vs` 核心的 `localize()` 英文串时，必须同步 vendored 中文语言包同 key（`main.i18n.json`），否则中文界面仍显示旧译（见 `REPAIR-NOTES.md`）。
- `l10n.t(变量)` 属"非字面量"调用，键不会进 bundle——运行时回填（`l10n.t(p.name)`、`localizeWebviewText`）除外，其键由 data-keys.json / HTML 占位扫描覆盖。
- agent-os 有少数工具输出串（回传模型、不直达用户）刻意保留中文，属正常残留，非遗漏。
- `idea-canvas.html` 的 `recognition.lang = 'zh-CN'`（语音识别语言硬编码）属功能逻辑，待产品层决策是否跟随界面语言。
- `npm run l10n:check` 已在根 package.json；仓库自评文档的"CI 已绿"历史上仅指本机 exit 0，接入远端 CI 前先核实。
