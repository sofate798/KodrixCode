# Kodrix — 项目非常有必要新实现的核心功能总报告

> **整理日期**：2026-09-24  
> **资料来源**：原码枢体验提升方案、体检报告「后续建议」、与 Cursor / Windsurf / Qoder / Kiro 差距矩阵（已合流至本文，旧稿已归档删除）  
> **定位**：在「已修复缺陷」与「待修债务」之外，列出**必须新做或大幅升级**才能形成差异化壁垒的核心能力  
> **原则**：少而硬 —— 优先 P0/P1 与不可替代壁垒；体验打磨与架构底座服务这些能力

---

## 一、为什么必须新做（一句话）

Kodrix 在 Cursor 式基线能力上已基本齐备；真正拉开差距的缺口不在「再抄一个按钮」，而在：

1. **越用越聪明**（语义记忆 + 主动上下文）  
2. **多 Agent 真协作**（角色编排，而非只开多个会话）  
3. **代码理解落地**（语义 Wiki / 调用图，而非静态目录）  
4. **大厂级交互闭环**（引导、审阅、时间线、Webview 体感）

## 三、P0 — 非常有必要、应立刻落地

### 3.1 渐进式首次引导（First-Run）

| 项 | 内容 |
|----|------|
| **要解决的问题** | 现有欢迎向导可用，但环境感知弱、导入结果不透明、冲突无选择 |
| **必须交付** | ① 检测 Ollama/GPU 等并推荐模型 ②「从哪迁移」一键导入 ③ 导入摘要（Rules/MCP/Skills 计数）④ 冲突时用户选择 ⑤ 每步可 Skip |
| **落点** | `extensions/kodrix-local` 欢迎向导 / onboarding |
| **验收** | 新用户 3 步内能跑通本地或云端一条 Chat；导入后设置无被静默覆盖 |

### 3.2 Chat 面板体验升级（每日路径）

| 项 | 内容 |
|----|------|
| **必须交付** | 上次路由提示；@mention 补全 Skill/Spec 等；Token/字符估算；消息内代码高亮预览；变更 diff stat（+N/-M）；会话「学习沉淀数」与一键 Memory |
| **落点** | `kodrix-local`（如 cursor3Experience）+ Copilot Chat 编排层 |
| **验收** | 不离开 Chat 即可完成「选对模式 → 看清改动 → 沉淀学习」 |

### 3.3 Webview UI 现代化（Spec / Hub）

| 项 | 内容 |
|----|------|
| **必须交付** | 骨架屏、面板过渡、按钮微交互、构建步骤指示器、终端日志分色、继承 VS Code 亮暗主题变量 |
| **落点** | `spec-workbench.html`、`kodrix-hub.html` |
| **验收** | 冷启动加载不再「空白闪一下」；主题切换无硬编码色翻车 |

## 四、P1 — 核心壁垒（不做则「有功能无记忆」）

### 4.1 Learning Engine 2.0：语义记忆

| 项 | 内容 |
|----|------|
| **现状** | JSONL + 关键词匹配 |
| **必须新实现** | 本地 embeddings（或 Copilot embeddings）；Top-K 余弦检索；LLM 自动分类与条目关联；时间衰减；交互式 Learning 仪表盘（替代纯 Markdown） |
| **可选增强（同阶段或紧随）** | 全局记忆池 `~/.kodrix/memory/global/`；相似项目检测与迁移提示 |
| **验收** | Agent 任务中可稳定注入相关记忆；仪表盘可搜/筛/编辑 |

### 4.2 主动上下文感知（Proactive Context）

| 项 | 内容 |
|----|------|
| **必须新实现** | 打开文件状态栏提示相关 Memory/Wiki；Chat 意图检测建议附加上下文；输入框旁上下文摘要（KB/条数/约 Token）可一键切换；隐式上下文（当前文件、最近编辑、Git diff、Linter） |
| **验收** | 默认路径下用户少手动 `@` 也能带上正确上下文 |

### 4.3 共享状态管理（架构底座）

| 项 | 内容 |
|----|------|
| **必须新实现** | 跨扩展 Event Bus（如 `kodrix:wiki.updated` / `learning.new` / `agent.session.*`）；内存统一 Store（当前会话、活跃 Agent、构建进度） |
| **验收** | Hub / Spec / Learning / Chat 侧栏状态实时一致，不靠反复读盘 |

### 4.4 Checkpoint 时间线 + Diff 画廊

| 项 | 内容 |
|----|------|
| **必须新实现** | 侧栏/底栏时间线（摘要 + 回退）；多文件 Diff 画廊；逐文件接受/拒绝/修改；批量操作 |
| **验收** | 多文件 Agent 改动可审阅且可单文件回滚（与现有安全路径校验兼容） |

## 五、P2 — 差异化杀手锏（中期必做）

### 5.1 Agent Crew 真协作

| 项 | 内容 |
|----|------|
| **现状** | 多会话并行，**互不协作** |
| **必须新实现** | 角色（Architect / Coder / Reviewer / Tester / DevOps）；顺序/并行流水线；审批门；`.kodrix/crew.json`；共享 Memory/Wiki/Spec；完成通知与同文件冲突策略 |
| **延伸** | 主 Agent 任务分解 → 子 Agent 汇报汇总；执行树 + Kanban；关键点人工介入 |
| **验收** | 一个大需求可走完「设计→实现→审查」且状态可视 |

### 5.2 语义代码理解 + Wiki 2.0

| 项 | 内容 |
|----|------|
| **现状** | 本地符号索引已有；Wiki 偏静态；`#codebase` 仍可依赖 Copilot 远端 |
| **必须新实现** | Tree-sitter AST → 调用图/依赖图；LLM 模块职责与 API 文档；Code Smell 标注；Hub 内交互关系图；**本地索引优先**为默认策略（对齐体检建议） |
| **验收** | 无 GitHub 登录时本地问答与 Wiki 仍可用且质量明显优于纯目录扫描 |

### 5.3 Vibe Coding 模式深化

| 项 | 内容 |
|----|------|
| **必须新实现** | 一句话选栈初始化；迭代式小改（只动相关文件）；自动 Checkpoint；预览/HMR 与错误叠加「一键让 Agent 修」（可分阶段） |
| **验收** | 非专业用户能从一句话到可运行雏形，且可回退 |

## 六、P3 — 强烈建议但可稍后

| 功能 | 要点 | 工期感 |
|------|------|--------|
| **Code Lens for Agents** | 函数上「优化/测/解释」；Diff 原因注解；影响分析 | ~5 天 |
| **命令面板自然语言 + Leader Key** | Router 解析「审查 PR」等；`Ctrl+;` 码枢模式 | ~5 天 |
| **跨项目知识迁移** | 全局记忆 + 栈相似检测 + 导入确认 | ~7 天 |
| **Session Learning 多维蒸馏** | 模式/错误-修复对/决策结构化；边跑边学；引用效果反馈 | 随 Learning 2.0 |
| **性能** | 非关键 Webview 延迟加载；不可见释放；Wiki 增量；Learning 检索缓存 | 持续 |

## 八、建议落地节奏（与原 Phase 对齐）

| 阶段 | 时间盒 | 交付焦点 |
|------|--------|---------|
| **Phase 1** | 0–2 周 | P0 三项（引导 / Chat / Webview） |
| **Phase 2** | 2–4 周 | Learning 2.0 + 主动上下文 + Event Bus |
| **Phase 3** | 4–6 周 | Agent Crew 协作 + 委派树 |
| **Phase 4** | 6–8 周 | 语义 Wiki / 调用图 / 本地优先 |
| **Phase 5** | 8–10 周 | Vibe 深化 + 时间线打磨 + P3 加分项 |

**Quick Wins（1–2 天，可插入 Phase 1）**：Spec 骨架屏 CSS、按钮涟漪、Router 增加审查/测试/文档意图、Chat 上次模式提示条。
